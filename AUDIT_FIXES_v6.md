Every finding in the audit was addressed. Verification: `:app:testDebugUnitTest` — **50/50 pass** (was 0 tests); `:app:assembleDebug` — **BUILD SUCCESSFUL**; Room schema exported (`app/schemas/…/3.json`).

## Critical findings

| # | Finding | Status | What shipped |
|---|---|---|---|
| C1 | No investor profile / suitability | **Fixed** | `InvestorProfile` (horizon, risk tolerance, risk-per-trade %, position cap %, sector cap %) in Settings. `PortfolioAdvisor` derives every cap, trim target, loss rule, and profit rule from it and cites it (`policyNote` on each review; cached reviews invalidate on profile change). Buy plans size from it. Unset profile = labeled balanced defaults. Tests prove different profiles produce different sizing. |
| C2 | Portfolio truth incomplete/inconsistent | **Fixed** | Oversells **rejected** in the add form (live + authoritative save-time check) and in edits (full-ledger replay validation); ReportsEngine now uses the same clamped quantities as the position engine, so totals can never disagree. New **cash ledger** (deposits/withdrawals/dividends/interest/fees → cash balance + total equity when tracked). **Splits** as first-class ledger rows handled by every replay consumer. Transactions carry **currency + FX rate**; non-USD bank alerts demand an explicit FX conversion in review and are barred from auto-import. Auto-import now requires a **broker transaction reference**, USD, all fields, confidence ≥80, plus a **ledger-level duplicate guard** (same BANK execution can never enter twice); everything else becomes a review notification. Dedup window 60s → 24h. Dashboard renamed to **Holdings value**; shows cash + total equity when tracked. Trade notes exposed in the form. *Not built: multi-account support, formal 12-statement broker reconciliation program.* |
| C3 | Advice from stale/partial/failed data | **Fixed** | `FeedStatus` (FRESH/STALE/FAILED) contract: news distinguishes verified-no-headlines vs stale vs failed on screen; scanners' empty states distinguish `NO_QUALIFYING_SETUP` / `PARTIAL_SCAN` (n of 8 screens) / `FETCH_FAILED` via `ScanCoverage`, with a universe line (screens/rows/as-of) under each scan; Analysis distinguishes short listing history from a failed candle fetch; unpriced holdings flagged "at cost — no price" and counted separately in the summary (never fake price + 0%); dashboard shows "prices as of" when >15 min old; MarketPulse computes measured-input **coverage** and **fails closed** to a new `INCOMPLETE` call below 60% — a refusal, not a neutral score. |
| C4 | Uncalibrated "confidence"/"trusted"/probability language | **Fixed** | "Confidence" relabeled **indicator agreement** everywhere user-facing; ATR ranges labeled "ATR-projected — not a calibrated forecast interval". TechniqueEvaluator now grades on a **non-overlapping (stride-5) independent grid**, computes each stock's own **base rate** (weighted by the technique's bull/bear call mix), and reports a **Wilson 95% CI**. Trust bar raised: ≥10 independent calls, ≥60% hit rate, **and ≥5-point edge over the base rate**; outlook-weighting minimum raised 5→10 calls. Record date-range shown; replay explicitly labeled in-sample, not predictive. *Not built: full walk-forward out-of-sample validation program (disclosed as a limitation in-app).* |
| C5 | Fixed $3,000 plan misstates the 2% rule | **Fixed** | `BuyPlanEngine.build` derives the budget from account equity (priced holdings + tracked cash): sized so a stop-out loses ≤ profile risk-per-trade % of equity, capped by position-size % and available cash; `riskPct` is now % **of the account**. With no account, it uses the $3,000 fallback and states plainly it is NOT the 2% rule. Elder principle text rewritten for both cases; the plan card shows the sizing basis. Unit-tested (risk cap, position cap, cash cap, linearity, stop-below-entry). |
| C6 | No company research/valuation | **Fixed (scoped)** | New quoteSummary client (cookie+crumb flow), `Fundamentals` model, cached repository with FRESH/STALE/FAILED provenance. Stock detail gains Company profile, Financial health (revenue, growth, margins, cash/debt/FCF/ROE, D/E, current ratio), Valuation (mcap, P/E, fwd P/E, P/B, EPS, dividend) with **bull/base/bear EPS×multiple scenarios** (formula disclosed; suppressed when inputs missing), Analyst view **with count + target dispersion + honest caveat**, and Catalysts (next earnings with ≤7-day event-risk flag, ex-div, payment date). Every missing field renders "—", never zero. *Not built: full statement tables/history, peer-comparison workspace, editable scenario assumptions.* |
| C7 | Zero tests, no CI, no schema export | **Fixed** | 50 unit tests across 6 suites: ledger replay golden vectors (avg cost, fees, oversell, splits, plOverride, day-P/L), TradeParser (EN/AR/currency/ref/clock-trap/JSON round-trip), Indicators (SMA/RSI Wilder vector/ATR/Pearson), BuyPlan sizing, NewsSentiment (negation/dedup/tiers — caught a real bug: "misses" double-listed as negator), trust gates + Wilson CI, cash reconciliation, report/ledger consistency, equity-curve TWR/flows/drawdown. Room `exportSchema=true` with schema 3.json committed; explicit migration v2→v3. GitHub Actions CI (test + lint + assemble). |

## Honestly not done (and why)

- **Multi-account support, broker statement reconciliation program** (C2) — infrastructure beyond a single-user local app; the ledger now has the fields (currency, FX, cash, splits) that make it possible later.
- **Walk-forward out-of-sample model validation** (C4) — a research program, not a patch; every in-app claim now states the replay is in-sample and uncalibrated.
- **Full financial statements/history, peer workspace, editable valuation assumptions** (C6/H6) — the highest-value slice (profile, health, multiples, scenarios, analysts, catalysts) shipped; statement tables remain future work.
- **VaR/CVaR, factor models, stress scenarios** (H2) — the measured core (TWR, vol, drawdown, beta, Sharpe, correlation) shipped first.
- **Database encryption** (H5) — export/lock/retention shipped; SQLCipher left out deliberately (adds a native dependency; documented in disclosures).
